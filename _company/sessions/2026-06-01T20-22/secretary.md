## 📝 KPI 자동 추출 로직 및 데이터 구조 요구사항 보고 (현빈님 전달용)

**수신:** 현빈님
**발신:** 영숙
**날짜:** 2026년 6월 1일 (가정)
**주제:** 자동화 시스템의 KPI 측정 및 데이터 추출을 위한 기술 요구사항 정의

사장님, 시스템 안정성과 수익화 검증에 초점을 맞춘 데이터 소스 연결 전략에 따라, 각 KPI 항목별 자동 추출 로직과 필요한 데이터 구조를 다음과 같이 정리했습니다. 이 내용을 기반으로 ETL 레이어 구축을 진행할 수 있도록 준비하겠습니다. 😊

### 1. 기술적 요구사항 (Logic Requirements)

자동화된 파이프라인(`pipeline_executor.py` 및 Designer/Developer 출력물)에서 KPI를 추출하기 위해 다음의 로직이 필요합니다.

*   **추출 단계 (Extraction):**
    *   `pipeline_executor.py` 실행 로그 파일(JSON/Log 형식)을 **정기적**으로 모니터링하고 읽어 들여 원시 데이터(Raw Data)를 추출해야 합니다.
    *   Designer 및 Developer의 출력물에서 핵심 결과값(예: 성공률, 처리 시간, 생성된 자산 수)을 정확하게 파싱하는 로직이 필요합니다.
*   **변환 단계 (Transformation):**
    *   추출된 원시 데이터는 KPI 대시보드에 표시될 **비즈니스 지표**로 변환되어야 합니다. (예: 작업 실패율 $\rightarrow$ 콘텐츠 품질 위험도)
    *   이 과정에서 설정된 **ROI 기반의 가중치 및 정규화 규칙**을 적용해야 합니다.
*   **적재 단계 (Loading):**
    *   변환된 최종 KPI 값은 중앙 데이터 레이어(파일 또는 DB)에 구조화되어 저장되어야 하며, KPI 대시보드에서 **실시간 접근 가능**하도록 구성되어야 합니다.

### 2. 필요한 데이터 구조 (Data Structure Schema)

KPI 대시보드와 시스템의 연결을 위해 최소한 다음 세 가지 핵심 데이터 구조를 정의해야 합니다.

#### A. 파이프라인 실행 로그 스키마 (Extraction Source Schema)
`pipeline_executor.py`가 출력하는 로그 파일의 표준화된 JSON 또는 Log 형식으로, 모든 작업의 시작, 종료, 성공/실패 상태 및 측정값을 포함해야 합니다.

| 필드명 | 데이터 타입 | 설명 | KPI 연관성 | 필수 여부 |
| :--- | :--- | :--- | :--- | :--- |
| `timestamp` | datetime | 작업이 시작된 시점 | 시간 분석 | 필수 |
| `pipeline_id` | string | 특정 파이프라인 실행 식별자 | 추적 관리 | 필수 |
| `status` | string | 최종 결과 상태 (Success/Failure) | 성공률 측정 | 필수 |
| `duration_sec` | float | 전체 처리 시간(초) | 효율성 측정 | 필수 |
| `output_count` | integer | 생성된 자산 또는 결과물 수 | 생산성 측정 | 필수 |
| `error_code` | string | 발생한 오류 코드 (없으면 null) | 품질 위험도 측정 | 선택 |

#### B. KPI 변환 스키마 (Transformation Schema)
추출된 로그 데이터를 비즈니스 지표로 변환하기 위한 매핑 규칙을 정의합니다.

| KPI 항목 | 원시 데이터 소스 | 변환 공식/규칙 | 목표 측정 단위 |
| :--- | :--- | :--- | :--- |
| **작업 성공률** | `status` | $(1 - \frac{\text{Failure Count}}{\text{Total Run}})$ | % |
| **평균 처리 시간** | `duration_sec` | $\text{Average}(\text{duration\_sec})$ | 초(s) |
| **콘텐츠 품질 위험도** | `error_code`, `status` | (복합 로직 정의 필요) | 1~10점 |
| **생산성 지표** | `output_count` | $\text{Total Output} / \text{Time}$ | 단위 시간당 출력량 |

#### C. 최종 KPI 저장 스키마 (Loading Target Schema)
KPI 대시보드에 직접 연결될 최종 결과값의 구조입니다.

| 필드명 | 데이터 타입 | 설명 | 참고 사항 |
| :--- | :--- | :--- | :--- |
| `metric_name` | string | KPI 이름 (예: Process Success Rate) | 고정 값 |
| `value` | float/int | 계산된 최종 지표 값 | 변환 결과 |
| `time_period` | string | 측정 기간 (예: Daily, Weekly) | 필터링 기준 |
| `target_value` | float/int | 설정된 목표치 | 비교 기준 |
| `status` | string | 현재 상태 (On Track / At Risk / OK) | 시각화 용이성 |
