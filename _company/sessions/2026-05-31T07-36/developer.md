### ⚙️ VSM 통합을 위한 API 및 데이터 매핑 사전 검토 결과 (초안)

VSM 로직이 성공적으로 콘텐츠 제작 워크플로우에 통합되기 위해 필요한 핵심 데이터 흐름과 인터페이스를 다음과 같이 제안합니다. 이는 추후 실제 코드 구현 시 참조할 설계 기준이 될 것입니다.

#### 1. 입력 단계: 스크립트 $\rightarrow$ VSM 명령 매핑
**목표:** 텍스트 기반의 스크립트 변화를 시각적 전환점(B-roll/그래픽) 요구사항으로 정확히 변환합니다.

| 데이터 소스 (Input) | 필요한 정보 (Mapping Point) | 목표 출력 (VSM Command) | 비고 (안정성 검증) |
| :--- | :--- | :--- | :--- |
| **스크립트 텍스트** (Writer 산출물) | 주요 전환점(Scene Break), 감정 변화(Focus/Escape 상태 변화), 강조할 키워드 위치. | `VSM_Command` (예: `insert_transition('focus_to_escape', duration=2s, style='dynamic')`) | 스크립트 내의 명시적 지시문(`[CUT]`, 감정 묘사)을 패턴 매칭하여 추출해야 함. |
| **브랜드 가이드라인** (Designer 산출물) | 핵심 색상 코드, 폰트 계층 구조, 레이아웃 프리셋. | `VSM_Style_Config` (예: `{color: '#2C3E50', layout: 'blueprint'}`) | 모든 시각화 작업에 이 설정이 강제 적용되어야 함. |

#### 2. 처리 단계: VSM 실행 $\rightarrow$ 자산 생성 매핑
**목표:** 정의된 시각적 명령을 실제 이미지/애니메이션 자산으로 변환하는 과정의 안정성을 확보합니다.

| 데이터 소스 (Input) | 필요한 정보 (Mapping Point) | 목표 출력 (Asset Generation) | 비고 (안정성 검증) |
| :--- | :--- | :--- | :--- |
| **VSM Command** | 요청된 전환점의 복잡도(Complexity), 필요한 시각적 요소의 종류. | `Asset_Request` (예: `generate_visual('dynamic_flow', context='Focus')`) | 복잡도가 높을 경우, 생성 실패 확률이 증가하므로 난이도별 API 레벨 분리가 필요함. |
| **Stress Test 결과** | 이전 실행에서 발생한 병목 지점(Latency, Memory Error). | `Error_Report` (실패 코드 및 위치) | 이 결과를 다음 실행에 반영하여 반복적인 실패 패턴을 회피해야 함. |

#### 3. 출력 단계: 최종 검증 $\rightarrow$ 품질 보장 매핑
**목표:** 생성된 자산이 콘텐츠의 의도(KPI)를 충족하는지 최종적으로 확인합니다.

| 데이터 소스 (Input) | 필요한 정보 (Mapping Point) | 목표 출력 (Quality Check) | 비고 (안정성 검증) |
| :--- | :--- | :--- | :--- |
| **최종 자산** | 시각적 흐름의 일관성, 브랜드 색상 적용률. | `VSM_Validation` (패턴 준수 여부 확인) | VSM이 요구한 구조(Flow/Blueprint)가 최종 결과물에 정확히 반영되었는지 객관적으로 측정해야 함. |
