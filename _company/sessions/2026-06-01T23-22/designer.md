## 🔍 시스템 흐름 및 데이터 연결 로직 재확인

**1. 핵심 전제 재확인:**
*   **System Flow:** 좌측 프로세스 라인(Input/Process)과 우측 결과 데이터 영역(Output/Result)으로 명확히 분할되어 있으며, 이 구조가 시각적 일관성(VCVM)을 반영하도록 설계되었습니다.
*   **VCVM 규칙:** Primary Color(\#2C3E50) 강조 및 Flow Arrow를 통한 논리적 흐름 표현이 디자인 표준으로 확정되었습니다.

**2. 잠재적 불일치 분석 (Test File 실행 관점):**
개발된 테스트 파일(`test_pipeline_stability.py`)의 성공적인 실행을 위해서는 다음 두 영역 간의 연결이 완벽해야 합니다.

*   **디자인 요구사항 $\rightarrow$ 데이터 구조 매핑:** 썸네일 디자인에 사용되는 시각적 요소(예: 흐름의 강도, 색상 대비)가 ETL 파이프라인에서 추출하고 측정하는 KPI 데이터 필드와 정확하게 일치해야 합니다.
*   **시스템 안정성 $\rightarrow$ 시각적 출력:** 파이프라인의 성공/실패 상태(`success` 플래그)가 최종 결과물(예: 썸네일 생성 실패 또는 성공)에 대한 시각적 피드백을 제공하도록 흐름이 정의되어야 합니다.

**3. 수정 계획 (Correction Plan):**
테스트 파일 실행 보장을 위해 System Flow의 다음 단계와 데이터 연결 로직에 대해 다음과 같이 수정 계획을 수립합니다.

### **Phase 1: Data Mapping 강화 (입력 $\rightarrow$ 처리)**

*   **목표:** 디자인 가이드라인(VCVM)을 파이프라인 입력 변수로 명시적으로 정의하여, 시각적 규칙이 데이터 로직에 직접 반영되도록 합니다.
*   **수정 내용:** `System Flow` 내의 **'Input Data Definition'** 단계를 강화합니다.
    *   **Action:** 디자인 브리프(`sessions/2026-05-31T07-36/designer.md`)에서 정의된 핵심 시각 변수(예: 강조 색상 코드, Flow 방향 벡터)를 파이프라인의 입력 매개변수로 직접 포함하도록 수정합니다.
    *   **연결 로직:** `Input Data`가 `System Flow`의 각 프로세스 단계로 들어갈 때, 이 시각적 변수가 데이터 필드에 **매핑(Mapping)**되는 과정을 명시적으로 추가합니다. (예: `Design_Flow_Vector` $\rightarrow$ `Process_Direction_Flag`)

### **Phase 2: Stability Feedback Loop 구축 (처리 $\rightarrow$ 출력)**

*   **목표:** 시스템 안정성(`success` 또는 `failure`)이 시각적 결과물에 대한 명확한 피드백으로 즉시 연결되도록 보장합니다.
*   **수정 내용:** **'Output & Validation'** 단계에 안정성 검증 로직을 통합합니다.
    *   **Action:** 개발된 테스트 파일에서 확인된 실패 원인 분석(`developer.md` 참조)을 기반으로, 시스템이 실패 시 생성하는 **에러 로그 포맷**을 디자인 가이드라인의 톤앤매너(전문적이고 기술적인 느낌)를 반영하여 표준화합니다.
    *   **연결 로직:** 파이프라인 실행 결과(`success`/`failure`)가 최종 사용자에게 보여줄 피드백 레이어에 직접 매핑되도록 `System Flow`의 마지막 단계를 수정합니다. (예: 성공 시에는 VCVM 규칙을 준수하는 고품질 썸네일 생성, 실패 시에는 오류 원인과 재실행 계획을 포함한 상세 리포트 출력).

### **Phase 3: 최종 검증 및 실행 준비**

*   **목표:** 수정된 흐름이 테스트 파일의 성공적인 실행을 보장하는지 확인합니다.
*   **Action:** Phase 1과 Phase 2의 수정 사항을 반영하여 `System Flow`를 업데이트하고, 코다리 에이전트에게 이 수정된 로직으로 **재검증(Re-validation)**을 요청합니다.
