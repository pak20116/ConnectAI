💼 현빈: 작업 시작합니다.

CEO의 지시에 따라, 개발된 썸네일 자동화 시스템의 초기 실행 결과를 측정하고 이를 KPI 대시보드에 연결하는 데이터 흐름을 최종 점검하고 최소한의 API 엔드포인트를 설계하겠습니다. 이는 **수익화 모델 검증**과 **ROI 측정**이라는 핵심 목표 달성을 위한 필수 단계입니다.

이 작업은 기술적 구현(코다리)과 비즈니스 정의(현빈)가 교차하는 지점이므로, 데이터 구조와 흐름의 일관성을 최우선으로 확보하겠습니다.

### 1. 요구사항 분석 및 전략 설정
핵심 목표는 **'썸네일 시스템 실행 결과 (CTR)'**를 측정하고 이를 **KPI 대시보드**에 연결하는 것입니다.

*   **측정 대상:** 각 자동 생성된 썸네일의 실제 클릭률(CTR) 데이터.
*   **중요성:** 이 데이터는 시스템의 가치(System Flow)가 실제로 시장에서 유효한지 검증하는 가장 중요한 지표입니다.
*   **전략 방향:** API 설계 시, 단순히 데이터를 반환하는 것을 넘어 **'어떤 프로세스 결과'**인지 명확히 정의하여 대시보드 연동의 신뢰도를 높여야 합니다.

### 2. 최소 요구사항 기반 API 엔드포인트 설계 (Spec)

데이터 흐름을 최종 점검하기 위해, 백엔드에서 제공해야 할 최소한의 데이터 구조를 정의합니다. 이 스펙은 코다리 에이전트가 구현할 API 명세서로 사용됩니다.

**API 엔드포인트 제안:** `/api/v1/pipeline_metrics` (또는 `/api/v1/thumbnail_results`)

| 필드명 (Field Name) | 데이터 타입 | 설명 (Business Context) | 필수 여부 | 비고 (VCVM 연관성) |
| :--- | :--- | :--- | :--- | :--- |
| `pipeline_id` | String | 해당 실행 프로세스의 고유 ID. (ETL/Flow 안정성 측정용) | O | 시스템 안정성 확보 |
| `thumbnail_id` | String | 생성된 개별 썸네일의 고유 식별자. | O | 결과 추적 |
| `process_name` | String | 적용된 프로세스 흐름 (예: "System Flow") | O | 시각적 일관성 반영 |
| `source_data` | Object | 원본 데이터의 요약 정보 (Source 데이터의 무결성 확인) | O | 데이터 깊이 확보 |
| `output_result` | Object | 최종 결과 및 측정 지표. **(핵심 KPI)** | O | CTR, 전환율 등 포함 |
| `metrics` | Object | 핵심 성능 지표. (예: `ctr`, `conversion_rate`) | O | 수익화 검증 |
| `timestamp` | DateTime | 데이터가 기록된 시간. | O | 시계열 분석 |

### 3. 데이터 흐름 최종 점검 및 실행 계획

현재의 데이터 흐름은 **(Source $\rightarrow$ Process $\rightarrow$ Output)** 구조를 따르고 있으며, 이를 KPI 대시보드에 연결하기 위해서는 다음 단계를 반드시 거쳐야 합니다.

1.  **데이터 추출 (Extraction):** `pipeline_executor.py`가 모든 실행 결과를 위에서 정의한 JSON 포맷(`output_result`, `metrics`)으로 기록하도록 수정합니다.
2.  **변환 및 정규화 (Transformation):** ETL 과정에서 측정된 CTR, 전환율 등의 지표를 KPI 대시보드 레이어에서 요구하는 표준 단위로 변환합니다.
3.  **로드 (Loading):** 최종적으로 정규화된 데이터셋을 KPI 대시보드가 접근할 수 있는 데이터베이스(또는 시계열 저장소)에 로드합니다.

**실행 지침:** 코다리 에이전트에게 위에서 정의한 API 스펙과 데이터 흐름 요구사항을 전달하여, `pipeline_executor.py`의 최종 로딩 모듈 구현을 즉시 시작하도록 지시합니다.
